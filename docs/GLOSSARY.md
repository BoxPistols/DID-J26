## 航空・ドローン関連

### DID（人口集中地区）

**読み**: ディーアイディー
**英語**: Densely Inhabited District

**説明**:
国勢調査で定められた「人口密度の高い地域」のこと。

**具体例**:
- 東京23区の大部分
- 大阪市中心部
- 名古屋市中心部

**ドローンとの関係**:
DID地区では、ドローンを飛ばすのに**国の許可が必要**です。

**このプロジェクトでの役割**:
DID地区を地図上に表示することで、「ここは許可が必要だよ」と視覚的に分かるようにしています。

---

### NFZ（飛行禁止区域）

**読み**: エヌエフゼット / ノーフライゾーン
**英語**: No Fly Zone

**説明**:
ドローンを飛ばすことが**法律で禁止されている区域**。

**具体例**:
- 空港周辺
- 自衛隊基地の上空
- 皇居周辺
- 原子力発電所周辺

**DIDとの違い**:
```text
DID    → 許可があればOK
NFZ    → 基本的にNG（例外的な許可のみ）
```

**このプロジェクトでの役割**:
NFZ区域を地図上に赤色で表示して、「ここは絶対ダメ」と警告しています。

---

### DIPS（ドローン情報基盤システム）

**読み**: ディップス
**英語**: Drone Information Platform System

**説明**:
国土交通省が運営する**ドローンの許可申請システム**。

**できること**:
- オンラインで飛行許可を申請
- 飛行計画を提出
- 許可証をダウンロード

**URL**: https://www.dips.mlit.go.jp/

**このプロジェクトでの関係**:
将来的に、DIPSのデータと連携して最新の飛行規制情報を表示する予定です。

---

### NOTAM（航空情報）

**読み**: ノータム
**英語**: Notice to Airmen（航空従事者への通知）

**説明**:
**航空関係者に向けた重要なお知らせ**。

**内容例**:
- 「〇〇空港の滑走路を補修工事中」
- 「△△地域で花火大会、上空飛行注意」
- 「××時〜××時、軍事訓練のため空域制限」

**ドローンとの関係**:
ドローンも航空機の一種なので、NOTAMの情報は重要です。

**このプロジェクトでの関係**:
NOTAM情報を地図上に表示する機能を検討中です。

---

### 高度

**説明**:
地面（海抜）からの高さ。

**単位**:
- メートル（m）
- フィート（ft）
  - 1フィート = 約30cm
  - 1000フィート = 約300m

**ドローンのルール**:
```text
地上150m以下  → 基本的にOK（DID等の規制は別）
地上150m以上  → 特別な許可が必要
```

---

### 空域

**読み**: くういき

**説明**:
空の中の**区域**。道路のように、空も区切られています。

**種類**:
```text
A空域 → 管制空域（許可が厳しい）
B空域 → 制限空域（条件付きOK）
C空域 → 非管制空域（比較的自由）
```

**ドローンとの関係**:
基本的に「地上150m以下」はC空域（非管制空域）ですが、空港周辺などは例外です。

## 地図・GIS関連

### GIS

**読み**: ジーアイエス
**英語**: Geographic Information System（地理情報システム）

**説明**:
地図上に様々な情報を重ねて表示・分析するシステム。

**具体例**:
- Google Maps（お店の位置、交通情報）
- ハザードマップ（浸水予想、避難所）
- このプロジェクト（DID、NFZ、天気）

**このプロジェクトでの役割**:
ドローンに関する様々な情報を地図上に重ねて表示しています。

---

### タイル

**説明**:
地図を**小さな画像に分割したもの**。

**イメージ**:
```text
大きな地図を、パズルのピースのように細かく分割
→ 必要な部分だけダウンロード
→ 高速表示
```

**メリット**:
- 軽量（全体をダウンロードしなくていい）
- 高速（見えている部分だけ読み込む）

**このプロジェクトでは**:
国土地理院のタイル地図を使用しています。

---

### ラスタータイル vs ベクタータイル

**ラスタータイル**:
PNG画像として保存された地図

```text
メリット:
- 見た目が美しい
- 互換性が高い

デメリット:
- 拡大するとボケる
- データサイズが大きい
```

**ベクタータイル**:
数値データとして保存された地図

```text
メリット:
- 拡大しても綺麗
- データサイズが小さい
- 色やスタイルを自由に変更できる

デメリット:
- 描画に処理能力が必要
```

**このプロジェクトでは**:
ベクタータイルを採用（高速＆カスタマイズ可能）

---

### レイヤー

**説明**:
地図上に重ねる**情報の層**。

**イメージ**:
```text
レイヤー1: 基本地図（道路、建物）
レイヤー2: DID区域（オレンジ）
レイヤー3: NFZ区域（赤）
レイヤー4: 天気予報（雲、雨）
レイヤー5: ユーザー位置（青い点）
```

**このプロジェクトでは**:
複数のレイヤーをON/OFFできます。

---

### ジオJSON（GeoJSON）

**読み**: ジオジェイソン
**英語**: Geographic JavaScript Object Notation

**説明**:
地図データを保存する**ファイル形式**。

**中身の例**:
```json
{
  "type": "Feature",
  "geometry": {
    "type": "Polygon",
    "coordinates": [[[139.76, 35.68], [139.77, 35.68], ...]]
  },
  "properties": {
    "name": "新宿区DID地区"
  }
}
```

**このプロジェクトでは**:
DIDやNFZのデータをGeoJSON形式で保存しています。

---

### 緯度・経度

**緯度（Latitude）**:
北緯・南緯を表す数値（-90〜90度）

```text
北極  →  90
東京  →  35.68
赤道  →   0
南極  → -90
```

**経度（Longitude）**:
東経・西経を表す数値（-180〜180度）

```text
ロンドン（本初子午線） →   0
東京                 → 139.69
ニューヨーク         → -74.0
```

**このプロジェクトでは**:
`[経度, 緯度]` の順番で記述（GeoJSON規格）

```typescript
// 東京の座標
[139.6917, 35.6895] // [経度, 緯度]
```

---

### ズームレベル

**説明**:
地図の拡大率を表す数値。

**レベル別の表示範囲**:
```text
0  → 地球全体
5  → 国全体
10 → 都道府県
15 → 市区町村
20 → 建物が見える
```

**このプロジェクトでは**:
デフォルトは**ズーム12**（区レベル）

## 開発技術関連

### TypeScript

**読み**: タイプスクリプト

**説明**:
JavaScriptに**型**を追加したプログラミング言語。

**JavaScriptとの違い**:
```javascript
// JavaScript（型なし）
function add(a, b) {
  return a + b
}
add(1, "2") // "12"（意図しない結果）

// TypeScript（型あり）
function add(a: number, b: number): number {
  return a + b
}
add(1, "2") // エラー！文字列は渡せない
```

**メリット**:
- バグが減る
- エディタの補完が効く
- 大規模開発に向いている

**読み**: ズスタント（ドイツ語で「状態」）

**説明**:

**例**:

  zoom: 12,
  center: [139.69, 35.68],
  setZoom: (zoom) => set({ zoom }),
}))

### Prettier

**読み**: プリティア

**説明**:

## その他

### CI/CD

**読み**: シーアイ / シーディー
**英語**: Continuous Integration / Continuous Deployment

**説明**:
コードを**自動でテスト＆デプロイ**する仕組み。

**CI（継続的インテグレーション）**:
```text
コードをプッシュ
↓
自動でテスト実行
↓
問題があれば通知
```

**CD（継続的デプロイ）**:
```text
テストが通過
↓
自動で本番環境にデプロイ
```

**このプロジェクトでは**:
GitHub Actionsで自動テストを実行。

### ホットリロード

**説明**:
コードを保存すると、**自動的にブラウザが更新**される機能。

**従来の開発**:
```text
1. コード編集
2. 保存
3. 手動でブラウザをリロード
4. 確認
```

**ホットリロードあり**:
```text
1. コード編集
2. 保存
3. 自動でブラウザ更新
4. すぐ確認
```

**このプロジェクトでは**:
Viteのホットリロードが有効です。
