## GitHub CLI 基礎

### インストール

```bash
# macOS (Homebrew)
brew install gh

# Windows (Chocolatey)
choco install gh

# Linux (apt)
sudo apt install gh

# バージョン確認
gh --version
```

---

### 認証

```bash
# 初回認証
gh auth login

# 選択肢
# ? What account do you want to log into? GitHub.com
# ? What is your preferred protocol for Git operations? HTTPS
# ? Authenticate Git with your GitHub credentials? Yes
# ? How would you like to authenticate GitHub CLI? Login with a web browser

# 認証状態確認
gh auth status

# 出力例:
# github.com
#   Logged in to github.com as BoxPistols (keyring)
#   Git operations for github.com configured to use https protocol.
#   Token: gho_************************************
```

---

### 基本コマンド

#### リポジトリ操作

```bash
# リポジトリをクローン
gh repo clone BoxPistols/DID-J26

# リポジトリを作成
gh repo create my-project --public

# リポジトリ情報を表示
gh repo view BoxPistols/DID-J26

# ブラウザで開く
gh repo view --web
```

---

#### プルリクエスト操作

```bash
# PR一覧
gh pr list

# PR作成
gh pr create --title "feat: 新機能追加" --body "詳細な説明"

# PR詳細表示
gh pr view 8

# PR詳細（JSON形式）
gh pr view 8 --json title,body,state,author

# PRをブラウザで開く
gh pr view 8 --web

# PRをチェックアウト
gh pr checkout 8

# PRをマージ
gh pr merge 8 --squash
```

---

#### Issue操作

```bash
# Issue一覧
gh issue list

# Issue作成
gh issue create --title "バグ報告" --body "詳細"

# Issue詳細
gh issue view 123

# Issueをクローズ
gh issue close 123
```

## GraphQL API の活用

GitHub CLI は GraphQL API を直接叩けるため、RESTよりも柔軟な操作が可能です。

### GraphQL vs REST の違い

| 機能 | REST API | GraphQL API |
|------|----------|-------------|
| データ取得 | 複数エンドポイント | 1エンドポイント |
| 過剰取得 | 発生しやすい | 必要なデータのみ |
| 複雑な操作 | 困難 | 容易 |
| 型安全性 | なし | スキーマベース |

---

### GraphQL 基本構文

#### Query（データ取得）

```bash
gh api graphql -f query='
{
  repository(owner: "BoxPistols", name: "DID-J26") {
    name
    description
    stargazerCount
    forkCount
    issues(first: 5, states: OPEN) {
      totalCount
      nodes {
        number
        title
        author {
          login
        }
      }
    }
  }
}
'
```

**出力:**

```json
{
  "data": {
    "repository": {
      "name": "DID-J26",
      "description": "ドローン飛行計画ツール",
      "stargazerCount": 10,
      "forkCount": 2,
      "issues": {
        "totalCount": 3,
        "nodes": [
          {
            "number": 1,
            "title": "バグ報告",
            "author": { "login": "BoxPistols" }
          }
        ]
      }
    }
  }
}
```

---

#### Mutation（データ変更）

```bash
gh api graphql -f query='
mutation {
  addComment(input: {
    subjectId: "PR_kwDOQ2E2785xxx",
    body: "LGTMです！"
  }) {
    commentEdge {
      node {
        id
        body
      }
    }
  }
}
'
```

### jqでデータ整形

GitHub CLI は `--jq` オプションで JSON を整形できます。

```bash
# PR一覧をタイトルとURLのみ表示
gh pr list --json number,title,url --jq '.[] | "\(.number): \(.title) - \(.url)"'

# 出力例:
# 8: refactor: デザインシステム刷新 - https://github.com/...
# 7: feat: 新機能追加 - https://github.com/...
```

**jq チートシート:**

```bash
# オブジェクトから特定フィールド抽出
--jq '.data.repository.name'

# 配列の各要素に処理
--jq '.[] | {title: .title, state: .state}'

# フィルタリング
--jq '.[] | select(.state == "OPEN")'

# カウント
--jq '.[] | length'

# ソート
--jq 'sort_by(.createdAt)'
```

## PR レビューコメントの一括操作

実践例：PR #8 の全レビューコメントを一括で Resolve する

### ステップ1: 未解決スレッドを取得

```bash
gh api graphql -f query='
{
  repository(owner: "BoxPistols", name: "DID-J26") {
    pullRequest(number: 8) {
      reviewThreads(first: 50) {
        nodes {
          id
          isResolved
          comments(first: 1) {
            nodes {
              body
              path
            }
          }
        }
      }
    }
  }
}' --jq '.data.repository.pullRequest.reviewThreads.nodes[] | select(.isResolved == false) | {id: .id, path: .comments.nodes[0].path, preview: .comments.nodes[0].body[0:80]}'
```

**出力例:**

```json
{
  "id": "PRRT_kwDOQ2E2785p3NzQ",
  "path": "src/components/AppHeader.tsx",
  "preview": "インラインスタイルで直接色を指定するのではなく..."
}
```

---

### ステップ2: スレッドIDを抽出

```bash
# スレッドIDのみ抽出
gh api graphql -f query='...' --jq '.data.repository.pullRequest.reviewThreads.nodes[] | select(.isResolved == false) | .id'
```

**出力:**

```
PRRT_kwDOQ2E2785p3NzQ
PRRT_kwDOQ2E2785p3NzT
PRRT_kwDOQ2E2785p3NzU
...
```

---

### ステップ3: 一括Resolve実行

```bash
#!/bin/bash
# resolve_threads.sh

# スレッドID配列
THREAD_IDS=(
  "PRRT_kwDOQ2E2785p3NzQ"
  "PRRT_kwDOQ2E2785p3NzT"
  "PRRT_kwDOQ2E2785p3NzU"
  "PRRT_kwDOQ2E2785p3NzV"
  "PRRT_kwDOQ2E2785p3NzW"
  # ... 全15個
)

echo "Resolving ${#THREAD_IDS[@]} review threads..."

for thread_id in "${THREAD_IDS[@]}"; do
  echo "Resolving thread: $thread_id"

  gh api graphql -f query="
    mutation {
      resolveReviewThread(input: {threadId: \"$thread_id\"}) {
        thread {
          id
          isResolved
        }
      }
    }
  " --jq '.data.resolveReviewThread.thread | "[Resolved] \(.id) - isResolved: \(.isResolved)"'
done

echo ""
echo "All threads resolved!"
```

**実行:**

```bash
chmod +x resolve_threads.sh
./resolve_threads.sh
```

**出力:**

```
Resolving 15 review threads...
Resolving thread: PRRT_kwDOQ2E2785p3NzQ
[Resolved] PRRT_kwDOQ2E2785p3NzQ - isResolved: true
Resolving thread: PRRT_kwDOQ2E2785p3NzT
[Resolved] PRRT_kwDOQ2E2785p3NzT - isResolved: true
...
All threads resolved!
```

## 実践例集

### 例1: 未解決PRコメントの自動通知

```bash
#!/bin/bash
# unresolved_comments.sh

PR_NUMBER=8
UNRESOLVED=$(gh api graphql -f query="
{
  repository(owner: \"BoxPistols\", name: \"DID-J26\") {
    pullRequest(number: $PR_NUMBER) {
      reviewThreads(first: 50) {
        nodes {
          isResolved
          comments(first: 1) {
            nodes {
              author { login }
              body
              path
            }
          }
        }
      }
    }
  }
}" --jq '[.data.repository.pullRequest.reviewThreads.nodes[] | select(.isResolved == false)] | length')

if [ "$UNRESOLVED" -gt 0 ]; then
  echo "WARNING: PR #$PR_NUMBER has $UNRESOLVED unresolved comments!"

  # Slack通知（例）
  # curl -X POST $SLACK_WEBHOOK -d "{\"text\": \"PR #$PR_NUMBER has $UNRESOLVED unresolved comments\"}"
else
  echo "All comments resolved!"
fi
```

### 例2: 特定ラベルのIssueを一括クローズ

```bash
#!/bin/bash
# close_outdated_issues.sh

# "wontfix" ラベルのIssueを取得
ISSUES=$(gh issue list --label "wontfix" --json number --jq '.[].number')

for issue in $ISSUES; do
  echo "Closing issue #$issue"
  gh issue close $issue --comment "Outdated issue. Closing."
done
```

### 例3: PRレビュー依頼の自動アサイン

```bash
#!/bin/bash
# auto_assign_reviewers.sh

PR_NUMBER=$1
REVIEWERS=("user1" "user2" "user3")

# ランダムに2人選択
SELECTED=$(shuf -e "${REVIEWERS[@]}" -n 2 | tr '\n' ',')

gh pr edit $PR_NUMBER --add-reviewer "$SELECTED"
echo "Assigned reviewers: $SELECTED"
```

---

### 例4: コミットメッセージの規約チェック

```bash
#!/bin/bash
# check_commit_messages.sh

# 最新10コミットを取得
COMMITS=$(gh api repos/BoxPistols/DID-J26/commits?per_page=10 --jq '.[].commit.message')

echo "$COMMITS" | while read -r msg; do
  # Conventional Commits形式チェック
  if ! echo "$msg" | grep -qE '^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?:'; then
    echo "INVALID: Invalid commit message: $msg"
  fi
done
```

---

### 例5: リリースノート自動生成

```bash
#!/bin/bash
# generate_release_notes.sh

PREVIOUS_TAG="v1.0.0"
CURRENT_TAG="v1.1.0"

echo "# Release Notes: $CURRENT_TAG"
echo ""

# feat コミットを抽出
echo "## New Features"
gh api repos/BoxPistols/DID-J26/compare/$PREVIOUS_TAG...$CURRENT_TAG \
  --jq '.commits[] | select(.commit.message | startswith("feat")) | "- \(.commit.message | split("\n")[0])"'

echo ""

# fix コミットを抽出
echo "## Bug Fixes"
gh api repos/BoxPistols/DID-J26/compare/$PREVIOUS_TAG...$CURRENT_TAG \
  --jq '.commits[] | select(.commit.message | startswith("fix")) | "- \(.commit.message | split("\n")[0])"'
```

## GraphQL スキーマ探索

### GitHub GraphQL Explorer

**URL:** [https://docs.github.com/en/graphql/overview/explorer](https://docs.github.com/en/graphql/overview/explorer)

ブラウザ上でGraphQLクエリを試せます。

---

### スキーマの調査

```bash
# リポジトリのフィールド一覧
gh api graphql -f query='
{
  __type(name: "Repository") {
    fields {
      name
      type {
        name
      }
    }
  }
}
' --jq '.data.__type.fields[] | "\(.name): \(.type.name)"'
```

**出力:**

```
name: String
description: String
stargazerCount: Int
forkCount: Int
issues: IssueConnection
pullRequests: PullRequestConnection
...
```

---

### よく使うオブジェクト

| オブジェクト | 用途 | 主なフィールド |
|-------------|------|--------------|
| `Repository` | リポジトリ情報 | name, description, issues, pullRequests |
| `PullRequest` | PR情報 | number, title, state, reviews, reviewThreads |
| `Issue` | Issue情報 | number, title, state, labels, comments |
| `ReviewThread` | レビュースレッド | id, isResolved, comments |
| `User` | ユーザー情報 | login, name, email |

## トラブルシューティング

### エラー1: 認証エラー

```
Error: HTTP 401: Bad credentials
```

**解決策:**

```bash
# 再認証
gh auth logout
gh auth login
```

---

### エラー2: GraphQLスキーマエラー

```
Error: Field 'xxxxx' doesn't exist on type 'Repository'
```

**解決策:**

```bash
# スキーマを確認
gh api graphql -f query='{__type(name: "Repository") {fields {name}}}'
```

---

### エラー3: Rate Limit

```
Error: API rate limit exceeded
```

**解決策:**

```bash
# Rate limit状況確認
gh api rate_limit

# 出力:
# {
#   "resources": {
#     "core": {
#       "limit": 5000,
#       "remaining": 0,
#       "reset": 1705612800
#     }
#   }
# }

# リセット時刻確認（Unix timestamp → 日時）
date -r 1705612800
```

**回避策:**

- 認証済みユーザーは 5,000 req/hour
- GraphQL使用でリクエスト数削減
- キャッシュ活用

---

### エラー4: jq構文エラー

```
parse error: Invalid numeric literal
```

**解決策:**

```bash
# jqデバッグモード
gh api ... --jq '.' | jq '.'  # まず生のJSONを確認

# よくある間違い
--jq '.items[0]'       # NG itemsが配列でない
--jq '.[] | .name'     # OK 配列の各要素を処理
```
